# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Marketing site for "FromSendr" (email-marketing agency, UK; copy uses UK English spelling: optimise, personalise, colour). Plain static site with five pages: `index.html` (landing), `services.html`, `work.html` (portfolio), `about.html`, `contact.html` (Calendly booking). Also `styles.css`, `script.js` (every page), `work.js` (work page only), the Tailwind build files (`tailwind.config.js`, `tailwind.input.css`, generated `tailwind.css`) and `images/`. There is no package.json, linter or test suite; the only build step is Tailwind (below).

## Running

Open `index.html` in a browser, or serve the folder statically (e.g. `python -m http.server`).

Fonts come from one Google Fonts request per page, so they need an internet connection: Poppins for body/UI (`font-sans`; 400/600/700 + 700 italic) and Space Grotesk for headlines (`font-display`; 500-600). It only asks for the weights in use: if you add a new weight class (e.g. `font-medium` on body text) or italic, add it to that URL on every page.

`.font-display` in `styles.css` gives headlines Space Grotesk's default weight (500) and `-0.02em` tracking; a Tailwind weight class on the element (`font-semibold`) still wins.

## Tailwind build (run after changing classes)

Tailwind is compiled ahead of time into `tailwind.css` (committed, and linked last in every page's `<head>`) by the standalone Tailwind CLI v3.4.17, a single exe, no Node needed. It lives in `.tools/tailwindcss.exe` (git-ignored; re-download from https://github.com/tailwindlabs/tailwindcss/releases/download/v3.4.17/tailwindcss-windows-x64.exe if missing).

- Build once: `.tools/tailwindcss.exe -i tailwind.input.css -o tailwind.css`
- While editing: add `--watch` to rebuild on every save.

Only classes that appear in the files listed in `tailwind.config.js`'s `content` (the pages, `script.js`, `work.js`) end up in `tailwind.css`, so **a class used for the first time does nothing until the build is re-run** (and removed classes linger until it is). Class names must appear as complete strings (don't build them by concatenation in JS). Don't pass `--minify`: its minifier rewrites translucent colours like `text-stone/30` into rounded `hsla()` values, shifting them by 1/255; the unminified file is only ~2 KB larger gzipped.

## Assets (keep them small)

Pages only reference optimised assets. The large originals are source files and must not be linked directly: `images/work/png-backups/<name>-full.png` (5-29 MB email screenshots), `images/wordmark-platinum.png` (3689px wide).
- Email screenshots: the user keeps the original PNGs in `images/work/png-backups/` and asks Claude to convert them whenever one is added or updated. Each PNG becomes two webps in `images/work/` (resized with LANCZOS, `quality=80`, `method=6`): `<name>-full-thumb.webp` (800px wide; work-page previews, work hero and archive strip) and `<name>-full.webp` (1200px; the modal's `data-full`). Always regenerate both. Some emails also have `images/work/tops/<name>-top.webp`: a 600x960 crop of just the top (20-70 KB), made from the 1200px webp, for the index hero, which only shows the tops.
- Footer wordmark: `images/wordmark-platinum-footer.webp` (400px). The nav uses `images/wordmark-platinum-nav.png` (614x128, see Site nav).
- Share image: `images/og-image.jpg` (1200x630, navy, wordmark, Space Grotesk headline, three email tops). Every page's `<head>` has a meta description plus Open Graph/Twitter tags pointing at it by absolute URL (`https://fromsendr.com/...`); if the domain changes, update `og:url`/`og:image` on every page.
- To make a new optimised copy, Pillow works (`python -m pip install pillow`, then save as WEBP with `method=6`).
- `images/brush-stroke.svg` is the painted stroke behind `.brush-stroke` text (index).
- Unused for now: `images/pfp.png`, `images/stickers/`, `images/hero-bg.webp`/`.png` (the old index hero collage).
- Below-the-fold `<img>`s (footer logos, grid/archive thumbs) use `loading="lazy" decoding="async"`.

## Architecture

- **Tailwind config lives in `tailwind.config.js`**: colours `paper`, `paperdark`, `ink`, `stone`, `blue`, `platinum`, `silver`, `navy`, `orange`, and fonts `font-sans` (Poppins, the body default) and `font-display` (Space Grotesk, the headline font). Use these tokens in class names rather than raw hex.
- **Colour use**: navy, blue, platinum, silver, paper and ink are the base palette. Orange is a sparing accent only (text-link arrows, the index eyebrow dot and typewriter, "money left on the table", the work page's "Featured" badge, palette swatches in illustrations). Don't cycle colours across repeated items (cards, badges, icons): repeated items share one colour, usually navy.
- **Type**: `font-display` for page headlines (h1), section headings, CTA headings, big stat numbers and small numerals; accent words in headings are `font-semibold text-blue` (no italics). Poppins (`font-sans`) for body, UI, card titles and labels. **Heading scale** (each level clearly smaller than the one above; nothing below a hero may match or beat its h1):
  - h1: index `lg:text-[2.5rem] xl:text-[2.875rem]`; inner pages `text-4xl md:text-[2.75rem]`.
  - Statement, the largest anything below a hero gets: `text-3xl md:text-4xl` (index's "More emails ≠ more results", the featured "Wild deodorant"; index's stat numbers are `text-4xl`).
  - Section heading: `text-2xl md:text-3xl` ("Who we are", "Selected work", "Questions, answered", the CTA card heading...).
  - Card title: `text-xl md:text-2xl` (about cards, "Your brand could be next"; services card titles `text-lg md:text-2xl`); numerals inside cards no bigger.
- **Motion**: deliberately minimal. Only the index typewriter (and its blinking cursor), hover states (buttons, links, email previews), the nav panel opening and the FAQ accordion move. No scroll-triggered animation, auto-scrolling or decorative animation.
- **`styles.css` only holds what Tailwind utilities can't express**: site nav mechanics, nav/footer link hovers, the `.btn` component, `.hero-full`, the static chart rules (`.return-donut`, `.share-bar-fill`), `.brush-stroke`, the CTA card's `.cta-glow`, the services FAQ open/close animation, and the work page's `.email-preview`/`.email-skeleton`/`.archive-*` rules. Its `:root` CSS variables are a separate palette from the Tailwind one; most values match, but `--color-paper` is `#FDFDFD` vs Tailwind `paper` `#FAFAF8`. Some rules (donut gradient, CTA glows, skeleton tints) hardcode hex/rgba too.
- **Buttons: every main CTA is `<a class="btn ...">` with a trailing `<svg class="btn-arrow">`.** `.btn` sets the look: solid blue with platinum Poppins text, `0.5rem` corners, shadow, and a platinum fill that slides in on hover/focus (text turns navy). The fill (`::before`) is a plain rectangle animated with `scaleX` and cropped by the button's `overflow: hidden`; don't give it its own `border-radius`, since scaling squashes those corners mid-animation. Colours come from `--btn-color`/`--btn-bg`/`--btn-border`/`--btn-fill`/`--btn-hover-color`, so a variant only overrides those. The base rules use `html body :where(.btn)` (specificity 0,0,2): high enough to beat Tailwind's preflight reset (`* { border-width: 0 }`, `a { color: inherit }`) regardless of stylesheet order, low enough that Tailwind classes on the element always win. Keep per-button classes to layout (width, margins, gap) and put anything visual in `styles.css`. Secondary links ("See our work", "Ask us directly") are plain text links with an orange `&rarr;` that nudges right on hover.
- **Nav, footer and the navy CTA card are duplicated in every page**: keep them in sync. The CTA card (index, services, work, about; each with its own heading and line of copy) has a `font-display` heading at section-heading size, `md:p-12`, the line of copy (where it's long, a shorter phone version: `<span class="hidden sm:flex">` long / `<span class="flex sm:hidden">` short) and the `.btn` ("Book a strategy call"); its two blue glows are the `.cta-glow` background. On `md+` the right-hand side is a straight paper "who you'll talk to" card, identical on every page: both founders as overlapping greyscale avatars (`images/people/*-avatar.webp`, 160px square crops), "You'll speak to / Jake or Tom (or both!) / Co-founders, FromSendr", three ticked points on what the call covers, and "30 min · Free". On phones that card is hidden and the avatars with "You'll speak to Jake or Tom (or both!)" sit above the button instead.
- **`script.js`** (vanilla JS, no modules) does these things, each a no-op on pages without the relevant markup:
  1. Site nav on touch devices (see below).
  2. Hero typewriter on `index.html` (`#typewriter`; the phrases are its `data-phrases` attribute, `|`-separated).

### Site nav (all pages)

**Booking button**: every page but `contact.html` also has a fixed "Book a call" `<a class="btn btn-sm site-cta hidden md:inline-flex">` right after the nav (top-right, vertically centred on the logo, `z-50` so it stays above the dropped-down panel; it doesn't change when the panel opens). Below `md` it's hidden, and the drawer instead ends with a full-width `btn btn-sm md:hidden mt-auto` "Book a call" button. `.btn-sm` (styles.css) is the compact, arrowless `.btn` variant.

Each page starts with a fixed, top-centre `<a class="site-logo">` followed by a sibling `<nav id="site-nav" class="site-nav">`. The logo is the whole white wordmark clipped to just the icon (`.site-logo-mark`, ratios from the 614x128 image with a 137px icon); opening the nav widens the clip to reveal the name. It uses `mix-blend-mode: difference`, so it renders as the inverse of whatever is behind it. That breaks if any ancestor creates a stacking context (transform, filter, opacity, isolation, z-index), which is also why the panel is a sibling rather than a wrapper, and why hero backgrounds have no z-index. The navy panel is hidden above the viewport and slides down on `.site-logo:hover ~ .site-nav`, `.site-nav:hover`, focus, or `.is-open`. Hover rules are gated to `@media (hover: hover)`, and closing has a short delay so moving the pointer from the logo onto the panel doesn't drop it. The current page's link uses `.nav-link-selected`. Nav/footer link hover fades and the nav's sliding underline are desktop-only (`min-width: 768px`).

Below `md` (a `max-width: 767px` query plus `md:` classes on the nav), the logo sits top-right and the panel becomes a full-height drawer (`min(75vw, 18rem)`, full width only on tiny screens) that slides in from the right. On touch, the first tap on the logo opens it instead of navigating (a second tap follows the link); tapping elsewhere or Escape closes it. While open, `script.js` locks page scroll (`overflow` on `<html>`, so it can't clash with the work modal's lock on `<body>`), a huge `box-shadow` spread dims the page, and a capture-phase click listener makes a tap on the dimmed area only close the drawer.

### Heroes

Only index fills the screen. Services, about and contact share one smaller version of the index hero: a `<header>` as tall as its content on the platinum page background, `pt-28 md:pt-32`, `grid gap-10 lg:grid-cols-[1.5fr_1fr] lg:gap-12 items-center`. Left: the small uppercase eyebrow, a `font-display` h1 at `text-4xl md:text-[2.75rem] leading-[1.08]` (index's scale; inner pages must not out-shout index) with one `font-semibold text-blue` word, one supporting line. Right: one piece of real material per page.

- **Index** (`.hero-full`: `min-height: 100svh` on `md+`, content height on phones): a light split on the platinum page background, no blur or card. Left (`lg:grid-cols-[1.5fr_1fr]`): uppercase eyebrow, a `font-display` navy headline "We build emails that" plus the typewriter line, one supporting line, the `.btn` ("Book a call with us") and a "See our work" text link, then "Free · 30 minutes · No obligation". Right (`lg+`): two staggered columns of real email tops (`images/work/tops/`), straight and at full strength, faded out at the bottom with a `mask-image`; below `lg` they become a short row of three under the copy. The typewriter cycles the `data-phrases` on `#typewriter` and alternates the typed line between `text-blue` and `text-orange` (the cursor is `bg-current`, so it follows). Invisible copies of every phrase share the line's grid cell so the heading never changes height while typing. Every phrase must fit on one line in the copy column, or the heading reserves two lines and leaves a gap: the headline is `lg:text-[2.5rem] xl:text-[2.875rem]` for that reason, so check the longest phrase at ~1040px and 1440px wide after changing phrases or sizes.
- **Services**: right = a numbered contents list of the five services (`md+`), each row an `<a href="#id">` to its card.
- **About**: left also has a `<dl>` of quick facts (what we do, who for, platform, how we work). Right = the founders (Jake, Tom; captioned "Co-founder") in two staggered `<figure>` columns like index's emails, under the copy below `lg`. Photos are 600x750 crops (`images/people/*-hero.webp`, ~23 KB, made from the PNGs in the same folder) shown with Tailwind's `grayscale` so two very different shots read as a set; they're placeholders, and when replacing them keep the same crop and size.
- **Contact**: right = a "What happens on the call" card (`md+`). Bottom padding is smaller so the Calendly widget sits just below.
- **Work**: the one dark hero, kept deliberately: a navy band (same eyebrow, h1 scale and top spacing as the others, centred), then the tops of five real email thumbnails (three on phones) rising from its bottom edge, staggered and cropped by the band. Navy is the work page's identity (its featured card and archive are navy too), so it reads as the gallery page rather than an inconsistency.

### Charts (index)

Static, pure CSS:
- `.return-donut`: a `conic-gradient` (350.27deg = 36/37 of a full circle).
- `.share-bar-fill`: width is the inline `--target`. Index's $0.18 vs $2.87 bars are `6%`/`100%` (to scale).
- Index's "2% of sends / 37% of sales" card uses two 10x10 waffle grids (100 `<span>`s each, the first 2 / 37 filled blue), so the filled squares read directly as percentages. Keep charts to scale.

## Page contents

To change an icon, replace the file and copy its `<path d>` into the inline SVG (keep `fill="currentColor"`, drop the file's own `fill="#000000"`); alternating sides on `md+` (below `md` they form a compact 2-column grid with a one-line summary, no illustration, plus a mobile-only 6th CTA card); `#process` (4 steps); `#faq` (native `<details>` accordion); CTA card. - **Work**: hero; a "Selected work" grid (2 columns, 3 from `lg`; below `sm` the cards show only the preview, no name/type/description). Under its heading, one line says the emails are uncommissioned concept work; that line is the only disclaimer, so don't repeat it per card. Card tags are blue for campaigns and navy for flows (welcome series, win-back, post-purchase), matching the colour key. Keep the card count a multiple of 6 so both layouts end on a full row. Each `<article data-work-item>` has a `<button data-open-email>` showing a cropped, fading preview (`.email-preview`); clicking opens `<dialog id="email-modal">` with the full email (`work.js`). `data-full` on the article is an image or an `.html` file (iframe); empty shows a tall skeleton. Placeholders use `.email-skeleton` (tints `-orange`/`-stone`/`-dark`). With a mouse it can also be click-dragged (`work.js`, pointer events, mouse only): sideways moves the row, up/down scrolls the email under the pointer, and presses on a scrollbar are left to the browser. No scroll-snap: mandatory snapping made scrollbar/trackpad scrolling jump a card at a time and fought the drag. Then the CTA card.

Every "book a call" CTA across the site points here.
